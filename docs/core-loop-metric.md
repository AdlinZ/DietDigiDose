# 每周核心闭环统计口径（实现中，#186）

版本：`weekly-core-loop-v1`。统计时区：`Asia/Shanghai`，自然周从当地周一 00:00 开始，到下周一 00:00 结束（不含）。通过 IANA 时区规则换算 UTC，不依赖服务器本地时区。查询可传入周内任一天。

## 有效闭环

同一持久化制作记录必须具备以下关联证据：

1. 已分类为真实用户，属于目标环境，使用独立于登录密钥的稳定最小用户标识。
2. 当前用户的推荐/选择来源与制作菜谱一致，选择时确实匹配了具体库存批次。
3. 至少一个被匹配的库存批次有更早的用户确认入库证据，且属于该用户或该次制作的同一家庭。
4. 制作事务确实扣减该批次。前后数量和扣减量一致，数量未知、只有客户端点击或没有持久化扣减的记录不计入。
5. 制作者本人有与该制作关联、已保存且未撤销/删除的实际摄入记录。单纯做完、家人吃了或保存待吃成品均不足以给制作者计数。

按首次仍然有效的摄入记录的**服务端提交时间**归周，不使用客户端回填的饮食日期。入库、选菜和制作可以发生在更早的周。同一批制作跨周分次食用仍只算一次闭环；同一用户同周多次闭环计一人，闭环次数另列。

撤销/删除首次摄入后，重算时选择下一条仍有效的实际摄入；因此可能移到另一周或完全不再计入。账号删除遵循现有删除策略，后续不保留该账号的逐条证据或纳入重算。

## 缺失、零值与覆盖

- `not_collected`：未配置目标环境/采集起点，或该周尚未进入采集范围；人数和闭环数是 null。
- `partial`：采集从周中开始，或有可能归属该周但来源证据不足的摄入；总人数和总闭环数是 null，另列已核实下限 `verifiedUsers` / `verifiedLoops` 与待核对条目数。
- `in_progress`：当前周尚未结束，显示截至查询时刻的实际人数。
- `complete`：完整覆盖已结束的周，无未判定证据。此时无有效记录才可以显示真实 0。

1–29 人显示实际人数及小样本标识，不输出百分比或因果结论。逐条核对只需制作 ID、稳定用户标识、状态和原因，不复制食物名称、营养/健康信息或原始对话。

## 当前验证与剩余接线

`server/src/modules/adminConsole/coreLoopMetric.ts` 已实现纯判定与周去重算法；固定用例覆盖跨年/跨周、此前周入库、重复制作、多个设备、非目标环境、演示/测试/自动化、未分类用户、缺失来源、未扣库存、数量未知、未食用、纠错、共享库存归属与 0/1/30 人。

**这还不是已上线的统计接口。** 下一步必须由 SQLite/PostgreSQL 仓库从真实持久化记录投影 `CoreLoopFact`，不能接受客户端提交的 `confirmed`、`verified` 或分类字段。还需落地账号分类与采集配置、稳定标识、受权限保护的查询和管理端展示，并执行写入失败/重算与真实业务事实对账。当前算法单测不替代这些集成验收。
