# 用户录入与资料管理改动

本轮沿用现有业务页面，替换统一七步身体资料引导。没有修改推荐排序算法或新增身份登录渠道。

## 用户流程

- 短信验证后，新账号自动生成公开昵称，可不设置密码；从业务页面登录时优先返回原任务。
- 首用提供库存、一餐规划、饮食记录、营养目标四个任务，支持跳过。食材与饮食记录不要求身体资料。
- 一餐条件包含人数、时间、饮食限制及是否接受补买。人数和时间默认只用于本次；未知限制需明确选择稍后填写。
- 口述先显示可编辑的摘要，确认后才进入表单或库存保存。拒绝录音/AI授权后仍可手动输入。
- 我的资料与偏好集中展示公开资料、饮食限制、厨房习惯、健康营养和偏好学习入口。各组独立保存，读取失败阻止提交，版本冲突保留草稿并提供合并。

## 数据与兼容

- 新健康资料的身体数值和活动水平为空。`calorieTarget` 是统一读取结果，区分 `unset`、`legacy_unconfirmed`、`user`；2000仅可作为有明确标注的参考值。
- `currentMeasurements` 按指标独立取最近有效测量，包含日期与来源；写入新体重时生成测量记录。
- `PATCH /api/v1/health-data/profile` 使用 `{version,...fields}`：省略保留、null清空、数组整体替换、嵌套对象逐字段合并。409包含最新档案，供客户端合并。
- 旧PUT保留已有字段语义，并接入同一热量同步服务；旧客户端回传相同数值不会把旧目标变为已确认，也不会将已清空目标恢复为默认2000。
- 首用 `GET/PATCH /api/v1/onboarding` 保存任务、步骤、暂停/完成与版本。完成依据为新增的所属库存/饮食记录、有效餐单或明确确认的目标版本；业务页面打开不算完成。业务响应后核验，GET可恢复未及时核验的状态。
- 客户端本机草稿按账号隔离，注销/退出清理。库存和手动饮食保存前持久化请求及固定幂等键；弱网后重试原请求。未确认口述原文不作为档案上传或持久化草稿。
- 饮食创建可选 `idempotency_key`，201首次、200重放、409同键不同内容、410原记录已删除。旧客户端无键请求保留兼容。

## 账号管理与发布

手机二次验证接口为 `/api/v1/auth/reauth/sms/send` 和 `/verify`，用途为 `password_update` / `account_delete`。验证码、复核凭证按用途与账号/会话绑定，短期有效且事务中一次性消费。设置首个密码、重设密码及无密码注销均可通过已绑定手机完成。密码变更撤销旧会话。

先发布数据库迁移及兼容后端，再发布客户端。SQLite迁移84–87与PostgreSQL迁移0026–0027必须一起部署。上线前按已有备份流程留存可恢复备份。

`SMS_PASSWORDLESS_REGISTRATION_ENABLED=0` 关闭新手机号自动创建无密码账号，回到旧短信注册接续流程；不会关闭已有无密码账号的短信登录、设置密码与注销。新客户端发送 `X-Account-Security: passwordless-v1` 能力标记；旧客户端访问不支持的无密码账号能力会收到明确升级提示。

沿用匿名actor散列的漏斗事件，新增 `onboarding_started`、`onboarding_completed`、`onboarding_resumed`、`onboarding_save_failed`，不包含资料或口述内容。正式上线前应留存生产基线，上线后按相同窗口比较完成率、开始至完成时长及恢复情况；本轮没有执行生产发布或读取生产统计。

本轮最终自动化结果：客户端77个套件、314项通过；服务端544项通过、1项跳过、无失败。`pnpm -w lint:all`、共享契约/OpenAPI兼容、数据库基线与Drizzle检查、模块边界检查通过。独立PostgreSQL 16实例执行完整迁移、备份恢复与账号/健康/首用/饮食幂等断言通过。Expo Web、Android、iOS导出通过；没有分配新打包编号。

客户端测试覆盖任务选择、限制未知、暂存条件、账号隔离、迟到响应、草稿清理竞态、表单冲突、重复点击、口述摘要与弱网请求恢复。服务端覆盖兼容注册、手机复核凭证消费、目标来源、测量投影、版本与空值语义、首用证据和幂等写入；另有真实PostgreSQL迁移与仓储集成断言。

本机Web人工验证了登录、四入口展示、一餐条件重载恢复、进入真实规划页面、资料中心、营养目标为空及保存成功反馈。未配置真实短信供应商与相机/麦克风测试输入；相关异常和账号安全流程由自动化测试验证。未连接Android设备，Expo导出不能替代真机权限、键盘、杀进程及弱网验收。
